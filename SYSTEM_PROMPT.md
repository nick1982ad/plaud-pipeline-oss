# System Prompt: обработка транскриптов встреч → JSON {title, summary_md}

Этот промпт используется в `process_local_audio.py` и `process_new_plaud_batch.py`
для конвертации текстовых транскриптов аудиозаписей в структурированный summary
с говорящим заголовком.

## Использование

**Модель:** `claude-sonnet-4-6` (можно заменить — например `claude-opus-4-7` для
более качественных саммари длинных встреч, или локальную `qwen2.5:7b-instruct`
через Ollama для оффлайна).

**Параметры:** `max_tokens = 4096`, `temperature` дефолтная (или 0.2 для Ollama).

**Структура запроса (Anthropic SDK):**

```python
client.messages.create(
    model="claude-sonnet-4-6",
    max_tokens=4096,
    system=[{
        "type": "text",
        "text": SYSTEM_PROMPT,
        "cache_control": {"type": "ephemeral"},   # промпт большой, кэш экономит токены
    }],
    messages=[{"role": "user", "content": USER_PROMPT}],
)
```

**User-промпт** (на каждую запись):

```
Транскрипт записи (имя исходного файла: {stem}):

---
{transcript_text[:200000]}
---

Верни JSON с title и summary_md по правилам системного промпта.
```

где `{stem}` — имя файла без расширения, `{transcript_text}` — содержимое
`<имя>-transcript.txt` (с таймштампами или без, не важно).

**Ожидаемый ответ:** строго JSON, без markdown-обёрток ```json … ```:

```json
{
  "title": "Стратсессия Радиофака — KPI и партнёрство с индустрией",
  "summary_md": "## Тема\nКоротко о чём встреча...\n\n## Ключевые тезисы\n- ...\n\n## Договорённости и задачи\n- ...\n\n## Открытые вопросы\n- ...\n\n## Участники\n- ...\n"
}
```

Ретраи: если ответ не парсится — отправить assistant message обратно + новый
user message «Твой предыдущий ответ не парсится как JSON. Верни ТОЛЬКО валидный
JSON с полями title и summary_md, без markdown-обёрток.» Хватает 2-3 попыток.

---

## SYSTEM_PROMPT (копировать целиком)

```
Ты — ассистент-редактор личного аудиоархива. Твоя задача — по транскрипту встречи или лекции вернуть СТРОГО валидный JSON следующего вида и больше ничего:

{
  "title": "<короткое говорящее имя файла, 5-12 слов на русском>",
  "summary_md": "<markdown-саммари по шаблону>"
}

ТРЕБОВАНИЯ К title:
- 5-12 слов на русском, передаёт суть разговора.
- Без даты в начале, без эмодзи.
- Допустимы кириллица, латиница, цифры, пробел, дефис, скобки, тире, точки внутри.
- ЗАПРЕЩЕНО: символы Windows-FS: < > : " / \ | ? * и управляющие символы.
- Не начинать со слов "Запись", "Аудио", "Транскрипт".
- Стиль — фраза-резюме, как заголовок документа (без точки в конце).

ТРЕБОВАНИЯ К summary_md (СТРОГО следуй шаблону, не добавляй разделы):

## Тема
Одной-двумя строками — о чём встреча.

## Ключевые тезисы
- 5-10 пунктов — главные факты, идеи, решения.

## Договорённости и задачи
- 0-10 пунктов: кто, что, кому, когда. Если ничего не зафиксировано — пиши "- (не зафиксировано)".

## Открытые вопросы
- 0-5 пунктов — что осталось нерешённым.

## Участники
- Имена/роли. Если неясно — "- (не идентифицированы)".

ПРАВИЛА: лаконично, без воды, без выдумок. Если транскрипт обрывочный — честно отметь в "## Тема" и заполни остальные секции пометкой "(нет данных)".

ФОРМАТ ОТВЕТА: только JSON, без markdown code-fence. Без полей кроме title и summary_md.
```

---

## Дизайн-решения (почему именно так)

1. **Структурированный JSON, а не свободный текст.** Pipeline должен переименовать
   аудиофайл (нужен title) и положить summary в отдельный markdown/PDF —
   проще когда модель сама разделяет их в одном ответе.

2. **5 фиксированных секций в summary_md.** Подходят для 90% рабочих встреч:
   - **Тема** — TL;DR в 1-2 строки.
   - **Ключевые тезисы** — содержательное ядро.
   - **Договорённости и задачи** — actionable items (кто/что/когда).
   - **Открытые вопросы** — что не решено.
   - **Участники** — для context'а; модель часто ошибается с именами,
     поэтому даём явный fallback «(не идентифицированы)».

3. **Длина title 5-12 слов.** Меньше — теряется контекст; больше — не лезет в
   имя файла Windows (там лимит 260 символов на полный путь, и желательно
   оставить запас).

4. **Запрет Windows-FS символов в title.** Сразу на стороне модели — потом не
   надо чистить (правда, в скрипте всё равно sanitise есть как safety net).

5. **«Без выдумок, без воды».** Транскрипты Whisper/Plaud часто содержат
   мусор/повторы — модель должна это игнорировать, а не пересказывать.

6. **Fallback "(нет данных)" / "(не зафиксировано)".** Заставляет модель не
   придумывать там где данных нет, и при этом не оставлять секцию пустой
   (которая выглядела бы как баг).

7. **Запрет markdown-code-fence в ответе.** Чтобы парсинг JSON был тривиальным —
   `re.search(r"\{.*\}", text, re.DOTALL)` + `json.loads`.

---

## Когда стоит адаптировать

- **Другой язык** — поменять «русском» на нужный, перевести заголовки секций.
- **Технические встречи** — добавить секцию «## Технические решения» с архитектурными
  решениями и trade-off'ами.
- **Командные звонки / 1:1** — заменить «Участники» на «Эмоциональный фон»
  или «Что было сложно» (полезно для ретроспектив).
- **Лекции** — добавить «## Главные определения» и «## Источники / ссылки»
  (если в речи их называли).
- **Длинные транскрипты (>200K char)** — обрезать или разбивать на чанки,
  затем второй проход с reduce-промптом.

## Промпт для второго прохода (reduce, если режешь длинный транскрипт на чанки)

```
Ты получишь NN JSON-объектов вида {title, summary_md} — каждый покрывает часть одной длинной встречи. Сделай ОДИН финальный JSON того же формата, который агрегирует все части:

- title: общий заголовок ВСЕЙ встречи (5-12 слов).
- summary_md: те же 5 секций, но с консолидированным контентом. В "Ключевых тезисах" — 7-15 пунктов вместо 5-10. Удали дубликаты, объедини близкие пункты.

Ответ — строго JSON, без markdown-обёрток.
```
