# Pipeline: локальная папка `.wav/.mp3` → структурированный summary

Для тех, у кого записи не в Plaud, а в обычной папке (диктофон, экспорт из Zoom, Telegram-кружки, Notes-iCloud — что угодно).

## Минимальный запуск

```bash
python bulk_export/process_local_audio.py --source "D:\AudioRecordings"
```

Результат — в `C:\_Dictophone\Записи с DD.MM.YYYY по DD.MM.YYYY\` (или в `--output`).

## Что внутри каждой записи

```
Записи с 05.06.2026 по 10.06.2026/
├── Стратегическая встреча про KPI и партнёрство.mp3        ← оригинал, переименован
├── Стратегическая встреча про KPI и партнёрство-transcript.txt
├── Стратегическая встреча про KPI и партнёрство.md         ← summary в markdown
├── Стратегическая встреча про KPI и партнёрство.pdf        ← summary в красивом PDF
├── ... другие записи ...
└── INDEX.md                                                 ← оглавление партии
```

## Поддерживаемые форматы

`.mp3 .wav .m4a .opus .ogg .flac` и `.mp4 .aac .wma` (Whisper умеет — это аудио-форматы или контейнеры с одной аудио-дорожкой).

Для **видео** (Zoom-mp4, mov-съёмка) используйте `process_lectures.py` или `process_shorts.py` — они извлекают аудио через ffmpeg.

## Идемпотентность

В source-папке появляется `.processed.json`:
```json
{
  "stem1": {"title": "...", "processed_at": "2026-06-10T12:34:56"},
  "stem2": {"title": "...", "processed_at": "2026-06-10T13:01:22"}
}
```

Повторный запуск читает этот файл и пропускает уже обработанные. Подложили новые файлы — обработаются только они.

## Определение даты

Скрипт пытается определить дату записи в следующем порядке:
1. `YYYY-MM-DD` в начале имени файла (`2026-05-23 meeting.wav` → 2026-05-23).
2. `MM-DD` в начале (`05-23 встреча.wav` → текущий год + 05-23).
3. `mtime` файла (последний fallback).

По диапазону дат формируется имя итоговой папки: `Записи с DD.MM.YYYY по DD.MM.YYYY` или `Записи за DD.MM.YYYY` если одна дата.

## Что если transcript уже готов

Если рядом с `recording.wav` уже лежит `recording-transcript.txt` (от Plaud, Otter, или ручной правки) — Whisper пропускается, transcript берётся как есть. Удобно для гибридного флоу.

## `--skip-whisper`

Для re-генерации summary по уже готовым transcripts:

```bash
python process_local_audio.py --source "..." --skip-whisper
```

Полезно если поменяли LLM-промпт или сменили `--backend`.

## `--backend auto | sdk | cli | ollama`

См. [README → LLM backend](../README.md#-llm-backend).

## Промпт LLM

См. [SYSTEM_PROMPT.md](../SYSTEM_PROMPT.md) — полный текст системного промпта с пояснениями, как и зачем он построен. Если хотите другой формат summary (например, без секции «Участники») — измените `SYSTEM_PROMPT` в `process_local_audio.py`.

## Резюме секций PDF/MD

| Секция | Что внутри |
|---|---|
| `## Тема` | 1-2 строки — о чём встреча. |
| `## Ключевые тезисы` | 5-10 пунктов — главные факты/решения. |
| `## Договорённости и задачи` | Action items: кто, что, кому, когда. |
| `## Открытые вопросы` | Что не решено. |
| `## Участники` | Имена/роли, если упомянуты. |
